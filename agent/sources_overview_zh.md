<h2 id="reading-overview">这些资料合起来讲了什么</h2>

这些资料共同描绘了一条 Agent 技术路线：**模型通过行动获取反馈，系统通过上下文与持久状态保持任务进展，工程环境通过权限、恢复和验收约束执行，最后用真实结果判断能力。** 下面是按主题整理的综合解读，不是任何一篇原文的单独结论。每份原文的摘要在后面逐项列出。

### 1. 从“生成答案”走向“执行并修正”

[ReAct](#source-03) 让推理和行动交替，[Plan-and-Solve](#source-04) 先分解再求解，[Tree of Thoughts](#source-05) 搜索多条候选路径，[Reflexion](#source-06) 将执行反馈转为下一轮经验。[Building effective agents](#source-02) 将这些能力放进实际架构选择：固定流程适合稳定任务，模型动态控制适合需要灵活决策的任务。它们合起来解释了 Agent 怎样形成反馈闭环，也说明规划、搜索和反思承担不同角色。

### 2. 可靠执行依赖模型以外的工程

[上下文工程](#source-08) 关注每轮该给模型哪些信息，[长任务 harness](#source-15) 强调功能清单、外部进度与测试交接，[Harness engineering](#source-16) 把仓库规范、可观察环境与自动检查纳入工程工作，[Agent Skills](#source-17) 则将流程打包并按需加载。综合来看，更长上下文和更详细提示只是部分手段；系统还需要可读取的状态、明确的步骤和可验证的成果。

### 3. 连接工具、委托 Agent 与保存记忆各有边界

[RAG](#source-07) 解决外部知识检索与生成结合的问题，[MCP](#source-09) 提供外部工具与资源的接口，[A2A](#source-10) 描述独立 Agent 间的任务交互。各家记忆文档进一步区分当前上下文、持久事实、历史检索和程序性技能。综合解读是：协议让系统能够通信，记忆让信息能够延续，但权限、安全与执行一致性仍要由运行时实现。

### 4. 五家产品是不同工程取舍，不能只比功能名字

OpenCode 的资料重点呈现客户端与服务端、会话处理、LSP 和可配置工具权限；OpenClaw 的资料突出长期运行的 Gateway、多入口路由、会话一致性与记忆；Hermes 的资料重点是持久会话、事实记忆、程序性 Skills 与可选工具后端；Claude Code 与 Codex 的官方文档展示编程工具循环、项目指令、子 Agent、审批和沙箱等能力。第 13 章的比较来自这些公开机制与固定版本代码，**没有据此推断未公开实现，也没有将它们写成实测能力排名。**

### 5. 前沿研究同时推进训练、协作和评测

[Search-R1](#source-18) 研究通过强化学习形成搜索策略，[Agent Lightning](#source-19) 与 [v1.0](#source-20) 探索执行与训练分离；[Multi-Agent Computer Use](#source-21) 研究按依赖调度并行任务。[Agent evals](#source-11)、[SWE-bench](#source-12) 和 [OSWorld](#source-13) 强调环境结果验收，[CoArena](#source-22) 探讨真实任务盲评，[SWE-Bench Pro Verified](#source-23) 审查评测漏洞。它们的共同提醒是：更多搜索、训练或协作必须在同任务、同预算和可靠评分下验证，才能确认收益。

### 怎么使用下面的导读

每条导读给出**主要内容**（原文讲什么）、**核心要点**（值得记住的内容）和**阅读提示**（与本指南的关系、适用条件或局限）。论文导读概括研究问题、方法与实验范围；文档导读概括接口与使用边界；源码导读解释固定版本的职责和关键控制流。正文每个外部引用旁的「导读」可跳到该小节的可见摘要，同一来源由同一份内容维护。
